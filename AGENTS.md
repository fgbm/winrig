# AGENTS.md — канон репозитория winrig

Истина для агентов и людей — документы этого репозитория. Если код расходится с документом, прав документ; расхождение чинится кодом или ADR, а не молчанием.

## 1. Продукт

`winrig` — MCP-сервер удалённого администрирования Windows-хостов по WinRM/NTLM, реализованный на Rust. Клиент вызывает инструменты: диагностика (только чтение) и модифицирующие операции (требуют подтверждения). Сервер работает из одного бинаря в двух режимах: HTTP-эндпоинт `/mcp` (`winrig serve`) для нескольких проектов и stdio-процесс (`winrig stdio`) для локального клиента; в обоих режимах используется один профиль учётной записи.

Продукт многопользовательский: несколько операторов одновременно в HTTP-режиме. `winrig` — самостоятельный преемник Python-проекта `win-mcp-server`; решения и правила перенесены оттуда, стек заменён на Rust ради низкого потребления памяти, скорости и одного статического бинаря без контейнера.

## 2. Архитектурные границы

- `src/main.rs` — точка входа: разбор CLI, код выхода.
- `src/app.rs` — оркестрация: подкоманды, журналирование, режимы serve/stdio.
- `src/cli.rs` — определения подкоманд `clap`.
- `src/client_config.rs` — запись определения MCP-сервера в конфиги клиентов (ADR-0009, ADR-0012).
- `src/profile.rs` — профиль учётной записи: шифртекст пароля, токен, ротация (ADR-0009).
- `src/paths.rs` — каталоги профилей и состояния, выбор профиля, lock процесса (ADR-0009).
- `src/private_fs.rs` — приватные файлы и каталоги `0700`/`0600`.
- `src/config.rs` — `AppConfig`, чтение и валидация переменных окружения (ADR-0003).
- `src/policy.rs` — решения «можно/нельзя»: allowlist хостов, режим понижения TLS, нормализация и классификация путей, защищённые префиксы (ADR-0003).
- `src/executor.rs` — редактирование секретов, усечение, экранирование полей и нейтрализация тела аудита (ADR-0003).
- `src/session.rs` — реестр WinRM-сессий (клиент создаётся на каждый вызов), TTL-кэш паролей, блокировка после отказов, аудит; транспорт отделён трейтом `WinRmTransport`.
- `src/ps.rs` — чистые генераторы PowerShell-команд.
- `src/identity.rs` — идентичность из заголовков или профиля (DR-2, ADR-0009).
- `src/auth.rs` — проверка общего секрета или токена профиля до доверия (DR-1, ADR-0009).
- `src/server.rs` — определения MCP-инструментов: валидация аргументов, `policy` → `session`.
- `src/logging.rs` — файлы журнала и аудита с ротацией и приватными правами.

## 3. Domain Rules (обязательны для кода и тестов)

- DR-1. **Аутентификация до доверия.** Каждый запрос обязан предъявить один из секретов: общий `WINRIG_AUTH_TOKEN` (путь по заголовкам, требует `X-AD-User`) либо токен профиля, расшифровывающий файл профиля. Совпадение `WINRIG_AUTH_TOKEN` с токеном профиля отказывает старту. Без хотя бы одного секрета сервер не стартует.
- DR-2. **Идентичность — на каждый запрос.** В HTTP пользователь, от имени которого выполняется инструмент, определяется предъявленным секретом текущего запроса: токен профиля даёт идентичность профиля и заставляет игнорировать `X-AD-*`, общий секрет требует `X-AD-User`. Идентичность не наследуется из задачи, создавшей MCP-сессию. В stdio идентичность равна профилю процесса.
- DR-3. **Изоляция кэшей.** Кэш пароля и сессии изолированы по пользователю. Пользователь не видит сессии другого.
- DR-4. **Секреты — только в памяти.** Пароли и парольные фразы не пишутся в логи, аудит, конфигурацию и не коммитятся. На диске допустим только аутентифицированный шифртекст профиля, ключ которого на сервере отсутствует. Секрет, переданный в команду, не должен появляться в аудите ни в одной форме.
- DR-5. **Модификация — только с подтверждением.** Любая изменяющая операция требует явного подтверждения; при отсутствии канала подтверждения операция не выполняется (fail-closed).
- DR-6. **Разрушительные операции защищены.** Удаление рекурсивно отказывает для корней томов и системных каталогов в любой форме записи пути и для точек повторной обработки (junction/symlink).
- DR-7. **Внешняя граница управляема.** Список разрешённых хостов и запрет понижения проверки TLS настраиваются через окружение.
- DR-8. **Отказ старта внятен.** Невалидная конфигурация останавливает процесс с сообщением, называющим переменную и ожидаемый формат.

## 4. Внешние системы и запись

- Windows-хост — внешняя система. Запись допустима только через инструменты, перечисленные в README как модифицирующие, и только после подтверждения (DR-5). Единственное исключение вне инструментов — запись определения MCP-сервера в конфиг выбранного клиента по явному флагу `setup --write-config` с уровнем `--scope global|project` (ADR-0009, ADR-0012). Никакой иной записи во внешние системы код не делает.
- Тестового Windows-хоста в окружении нет. Автотесты работают на фиктивном транспорте, реализующем `WinRmTransport` и записывающем переданные команды; сети не касаются (см. `src/session.rs::tests`).

## 5. Конфигурация

Все параметры — через переменные окружения (ADR-0004). Полная таблица — в README. Секреты — в `.env`; `.env`, `target/` и снапшоты не коммитятся. Файл профиля — не конфигурация, а хранилище шифртекста (ADR-0009); ключ профиля на сервере не хранится.

## 6. Тесты и качество

- Прогон: `cargo test`, `cargo clippy --all-targets -- -D warnings`, `cargo fmt --check` и `cargo deny check`. Полный прогон должен быть зелёным, clippy — без предупреждений, форматирование — без расхождений, cargo-deny — без отказов.
- Сначала тест, который падает, затем код.
- Проверки, чувствительные к локали хоста, выполняются в коде и покрываются тестом: PowerShell-команды не должны зависеть от языка системы.
- Зелёный полный прогон — обязательное условие коммита.

## 7. Коммиты и релизы

Атомарные, conventional-commit. Документы — отдельным коммитом с префиксом `docs:`. До коммита — полный прогон проверок.

Репозиторий публичный (`github.com/fgbm/winrig`), рабочая ветка — `main`. Внутренние журналы (`PAPERCUTS.md`) и локальные конфиги клиентов с токенами в публичную историю не попадают: они перечислены в `.gitignore`. Реальный домен и учётная запись в коде, тестах и документах заменяются обезличенными (`contoso\alice`).

Релиз ставится тегом `vX.Y.Z` на `main`. Версия в `Cargo.toml` и запись в `CHANGELOG.md` поднимаются одним коммитом до тега: workflow `release.yml` отказывает, если версия тега и манифеста расходятся, а текст релиза берёт из CHANGELOG. Тег запускает сборку бинарей под пять таргетов и GitHub Release.

## 8. Документы

- `docs/REQUIREMENTS.md` — требования `TR-*` и критерии приёмки `AC-*`.
- `docs/ROADMAP.md` — очередь срезов.
- `docs/IMPLEMENTATION_CYCLE.md` — цикл среза, пакет субагенту, чек-лист ревьюера, бэклог.
- `docs/QUESTIONS.md` — журнал вопросов `Q-NN`.
- `docs/adr/` — решения. Новые сущности, статусы, роли и каналы вводятся только через ADR.
- `AGENTS.md` — канон репозитория (этот файл). `CONTRIBUTING.md` — то же для внешнего участника, кратко.
- `SECURITY.md` — канал приватного раскрытия уязвимостей; сообщение о них не идёт в публичный issue.
- `CHANGELOG.md` — история изменений по Keep a Changelog; запись под тег — источник текста релиза.

## 9. Форматирование документов

- **Без мягких переносов.** Каждый абзац и каждый пункт списка занимает одну строку источника, как бы длинна она ни была. Переносить строку по ширине запрещено: это создаёт diff-шум при правках и мешает чтению. Разрешён только содержательный перенос — новый абзац, новый пункт списка.
- Строки, несущие смысл по строке, сохраняются как есть: заголовки, таблицы, блоки кода в ограждении, горизонтальные линейки, пустые разделители.
- Строки внутри блока кода не переносятся и не распаковываются.
- Многострочные абзацы и «съехавшие» продолжения пунктов недопустимы; существующие распаковываются.
