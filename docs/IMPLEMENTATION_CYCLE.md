# docs/IMPLEMENTATION_CYCLE.md — цикл среза, пакет субагенту, чек-лист ревьюера

## 1. Роли

- **Оркестратор** (основной агент): выбирает срез и его критерии, план, правки документов, ADR, журнала вопросов и roadmap, коммиты документов, финальный отчёт.
- **Исполнитель** — субагент: один шаг реализации или исследований.
- **Ревьюер** — субагент, всегда не автор кода: проверяет соответствие документам.
- **Прогонщик** — отдельный субагент (или оркестратор) запускает проверки; статус тестов берётся из прогона, а не со слов исполнителя.

## 1a. Команда прогона проверок

```bash
cargo test
cargo clippy --all-targets -- -D warnings
cargo fmt --check
cargo deny check
cargo build --release
```

Полный прогон должен быть зелёным, clippy — без предупреждений, форматирование — без расхождений, cargo-deny — без отказов, до коммита (AGENTS.md §6, §7). Версия Rust берётся из `rust-toolchain.toml`; CI (`.github/workflows/ci.yml`) выполняет тот же набор и отдельно собирает проект на MSRV из `Cargo.toml`.

## 2. Цикл на срез

0. **Срез.** Цель, критерии приёмки со ссылкой на раздел документа, `risky да/нет`, что вне среза. Критерий, не выводимый из документов, — это допущение `Q-NN` плюс строка в `docs/QUESTIONS.md`.
1. **План.** Не больше восьми шагов: файлы, тесты, риски, откат. Risky-срезы не ждут подтверждения: делаются обратимо.
2. **Реализация.** Шаг = сначала падающий тест, потом код. Ничего «заодно». Отклонение от документов — сначала документ или ADR-допущение, потом код.
3. **Тесты.** `cargo test`. Внешние системы — фиктивный транспорт, записывающий команды; живой канал не используется (AGENTS.md §4). Полный лог — в файл среза.
4. **Контроль.** Независимый ревьюер проверяет соответствие документам. Каждое «не выполнено» возвращает на шаг 2; каждое «не проверяемо» требует теста, протокола или уточнения документа.
5. **Документы.** README, AGENTS.md, ADR, `docs/QUESTIONS.md`, `docs/ROADMAP.md`. Отдельный коммит с префиксом `docs:`.
6. **Ретроспектива.** В `PAPERCUTS.md` — «что делал → что сломалось → обход». Журнал ведётся локально и не коммитится: он называет детали рабочего окружения, которым не место в публичной истории (`.gitignore`).

## 4. Чек-лист ревьюера

1. Каждый критерий приёмки среза имеет вердикт «выполнено / не выполнено / не проверяемо» с доказательством (тест, вывод, протокол).
2. Domain Rules (AGENTS.md §3) выполняются кодом и покрыты тестом.
3. Нет записи во внешнюю систему вне модифицирующих инструментов и вне подтверждения (DR-5).
4. Новые сущности/статусы/роли/каналы подкреплены ADR.
5. Нет ссылок на несуществующие файлы, команды, эндпоинты.
6. Секреты не попали в логи/аудит/код/коммит.
7. Проверки, чувствительные к локали, — в коде, с тестом.
8. Полный прогон `cargo test` зелёный и clippy чист на момент проверки.

## 5. Бэклог

Очередь и статусы — в `docs/ROADMAP.md`. Вне среза остаются (зафиксировано в `docs/QUESTIONS.md`):

- тестового Windows-хоста нет — NTLM-подключение, reparse-проверка и живой разбор вывода не проверены (Q-08);
- непортированные инструменты Python-версии (file transfer, архивы, `invoke_http_request`, SFTP);
- замена канала подтверждения на `input_required` при переходе на ревизию `2026-07-28` (Q-10); клиенты без elicitation (opencode 1.18.31) остаются fail-closed на модифицирующих инструментах;
- переиспользование WinRM-клиента на сессию и длительность в записи аудита;
- OS keyring как альтернатива файлу профиля (Q-12).
