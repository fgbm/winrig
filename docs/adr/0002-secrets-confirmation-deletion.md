# ADR-0002 — Секреты только в памяти, подтверждение модификаций, защита удаления

- Статус: принято
- Дата: 2026-09-19
- Связано: AGENTS.md §3 DR-4, DR-5, DR-6

## Контекст

Пароли AD попадали бы в логи и аудит, модифицирующие операции могли бы выполняться без подтверждения, а рекурсивное удаление — дойти до системных каталогов и точек повторной обработки.

## Решение

1. **Секреты только в памяти.** Пароли и парольные фразы не пишутся в логи, аудит, конфигурацию и не коммитятся. Пароль хранится в `secrecy::SecretString` и обнуляется при освобождении. Секрет, переданный в команду, редактируется из аудита во всех формах.
2. **Подтверждение обязательно.** Изменяющая операция выполняется только после явного подтверждения через elicitation; при отсутствии канала подтверждения не выполняется (fail-closed). Модифицирующий инструмент возвращает готовый ответ с полем `error`, а не выполняет команду.
2a. **Аудит не подделать.** Поля аудита экранируются (переводы строк и разделитель), а тело записи (команда и вывод внешней системы) нейтрализует символы-разделители блока, поэтому вставленный текст не может создать поддельную границу блока или поле. Хост и идентификатор сессии санируются и в основном журнале.
3. **Защита удаления.** Рекурсивное удаление отказывает для корней томов и системных каталогов в любой форме записи пути и для точек повторной обработки (junction/symlink).

## Последствия

- Редактирование секрета имеет минимальную длину (ADR-0005).
- Проверка пути нормализуется в коде (`src/policy.rs`).
- Пароль AD поставляется заголовком `X-AD-Password`; elicitation в спецификации MCP не предназначен для секретов и используется только для подтверждения (ADR-0006).
