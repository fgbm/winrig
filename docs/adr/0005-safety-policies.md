# ADR-0005 — Политики блокировки, редактирования, allowlist и идемпотентности

- Статус: принято
- Дата: 2026-09-19
- Связано: ADR-0002, ADR-0004, `docs/QUESTIONS.md` Q-01..Q-04

## Контекст

Требования фиксировали поведение, но не числовые значения и семантику. Человек подтвердил параметры в Python-версии; они переносятся как решение, чтобы код и тесты имели источник.

## Решение

1. **Блокировка (Q-01).** После `WINRIG_LOCKOUT_ATTEMPTS` (3) отказов **конкретного пароля** этот пароль не предъявляется повторно в течение `WINRIG_LOCKOUT_WINDOW_SECONDS` (1800) для этого пользователя. Отказ детерминированный, без обращения к AD; блокировка изолирована по пользователю. Предъявление **другого** пароля не блокируется. Окно отсчитывается от отказа, достигшего порога.
2. **Редактирование (Q-02).** `WINRIG_SECRET_REDACT_MIN_LENGTH` (4) управляет только редактированием **ответа агенту**: более короткие значения там не редактируются, чтобы не искажать полезный вывод. **Аудит-журнал подчиняется DR-4 безусловно**: на пути аудита секрет вырезается при любой длине (`min_length=1`).
3. **Allowlist (Q-03).** `WINRIG_ALLOWED_HOSTS` — список через запятую. Элемент — точное имя/IP без учёта регистра; элемент, начинающийся с `.`, — суффикс. Пусто — разрешать всё.
4. **Идемпотентность (Q-04).** Повторный модифицирующий вызов запрашивает подтверждение заново и повторно применяет операцию; автоматической дедупликации нет.
5. **Границы защиты путей (DR-6).** Защищёнными считаются: корни любых томов (`X:\` в любой форме записи, включая `\\?\`, `\??\`, `\\?\Volume{…}\`), системные каталоги и **всё их поддерево** (`C:\Windows`, `System32`, `Program Files`, `Program Files (x86)`, `Users`, `ProgramData`), а также **корень UNC-шара** `\\server\share` ровно на уровне шара. Нормализация повторяет `ntpath.normpath` из стандартной библиотеки CPython, потому что от неё зависит, сработает ли защита для экзотической формы записи.

## Последствия

Это обратимое допущение: каждый параметр — через окружение, значения можно изменить без выпуска кода.

## Дополнение (ADR-0009)

6. **Двойная блокировка профиля.** Если после истечения окна блокировки тот же пароль снова набрал порог отказов, а пароль пришёл из профиля, профиль переводится в отказ: в stdio процесс завершается с кодом 3, в HTTP каждый последующий `connect` по профилю отвечает ошибкой без обращения к транспорту до перезапуска процесса. Успешный `connect` сбрасывает счёт подряд идущих блокировок. Для пароля из заголовка поведение прежнее: клиент может сменить пароль вручную.
