# ADR-0014 — Work with Active Directory

- Status: accepted
- Date: 2026-09-21
- Related: ADR-0003, ADR-0005, ADR-0007, ADR-0013, DR-4, DR-5, DR-6, DR-7, Q-08, Q-15

## Context

The product has no work with the directory in any form. It has no tool, no line in the requirements and no mention in the section "What the product does not have". As with arbitrary execution before Q-14, this is not a decision of anyone, but a state of the code. 37 tools answer about the host on which they run, and not one asks the directory. At the same time the task of the operator is to administer the domain, and not a single computer.

The obstacle is not architectural, but protocol. `winrig` connects over WinRM with NTLM (`src/session.rs`, `AuthMethod::Ntlm` by default in `winrm-rs`). NTLM gives a network logon on the host: a token without delegable credentials. A request to the directory from a host that is a domain member is a second hop to the domain controller. It meets a refusal (`An operations error occurred`, LDAP 0x80072020). Three ways go around this, and all three have a price. CredSSP delegates the password to each host and lives in `winrm-rs` behind the feature `credssp`. That feature pulls `openssl` as a C dependency and breaks the promise of one static binary (ADR-0007). Explicit credentials in the text of the script put the password into the command line of each call. LDAP directly from the Linux host of winrig is a new external system with its own authentication, its own allowlist and its own TLS policy.

The fourth way has no price. If the host of the session is itself a domain controller, the request to the directory is local. There is no second hop, and there is nothing to delegate. The operator works exactly so.

## Decision

### Route

1. **An AD tool runs on the domain controller.** The session opens to the domain controller by the same `connect`/`disconnect`, the request to the directory goes to localhost and authorizes with the existing logon session. Neither the transport, nor the session model, nor the authentication changes. The AD tools are usual PowerShell generators in `src/ps.rs` behind the existing seam `policy` → `session` → `run_ps`.
2. **The script itself checks the role of the host.** `(Get-CimInstance Win32_ComputerSystem).DomainRole` with the value 4 or 5 means a domain controller; in the other case the tool refuses and names the reason. Without this the operator on a host that is a domain member gets `An operations error occurred`. The reason cannot be restored from that message, and it is exactly of the class that W14 examined. The check is numeric, so it does not depend on the locale.
3. **`System.DirectoryServices` instead of RSAT.** `Get-ADUser` and the other cmdlets go not to LDAP, but to ADWS (port 9389). Thus they depend on an installed `RSAT-AD-PowerShell` and on a started service. `[ADSI]`, `DirectorySearcher` and `System.DirectoryServices.ActiveDirectory` are .NET classes, they are always there, they go to LDAP on localhost and give raw attributes. Those raw attributes are easier to convert to a form that does not depend on the system language. The team did not check either of the two on a live domain controller (Q-08), and Q-15 records this as an assumption.
4. **CredSSP is rejected.** The price is a C dependency in the build and the delegation of the password to each host that receives the call. The gain is the capability to ask the directory from a host that is a domain member. The accepted route does not need that capability.
5. **Credentials in the text of the script are rejected.** `DirectoryEntry("LDAP://…",$u,$p)` puts the password into the command line of each call on the host. This is against the spirit of DR-4 and without need, since the request is local.
6. **LDAP directly from winrig is postponed, not rejected.** The route through `ldap3` removes the tie to the domain controller and gives a structural output without PowerShell. It also introduces an external system, a second kind of session and its own TLS policy. If AD becomes an independent direction, a separate ADR decides it; at present there is nothing to pay with.

### Common to the tools

7. **The escaping has two layers, and the order is mandatory.** The code first escapes a value from an argument by RFC 4515 (`\`, `(`, `)`, `*`, NUL → `\5c`, `\28`, `\29`, `\2a`, `\00`). It then applies `ps::escape` for the insertion into a PowerShell string in single quotes. The reverse order leaves a hole: the escaping of PowerShell does not touch the round brackets. `*)(objectClass=*` in an LDAP filter is the same thing as the PowerShell injection in `compare_files` before W8.
8. **A ceiling on the results.** Each tool that can return a set has an upper limit, and the answer names the achievement of the ceiling. A silent truncation of a selection from the directory is worse than a refusal. The agent builds a conclusion on an incomplete set, and it does not know this.
9. **Independence from the locale.** The code outputs the time (`FileTime` → `yyyy-MM-dd HH:mm` with the handling of `0` and `9223372036854775807`). It reads the state of an account from the bits `userAccountControl` and `lockoutTime`. It takes the state of replication from the classes `System.DirectoryServices.ActiveDirectory`. The code does not parse the output of `repadmin` or `dcdiag`. That output is localized, and the team already caught this class of defects on `whoami /priv` in W8.
10. **Symmetric operations group together; risky ones do not.** The kinds "user, group, computer" are the parameter `kind` of one tool, and not three tools. The queries "in which groups it is / who is in the group" are the parameter `direction`, and not two tools. Operations with different risks do not become different modes of one tool: `reset_ad_password` has its own confirmation text and its own price of a mistake. The reason is not aesthetics: with 60 declared tools the choice of the model becomes worse, and each request to it grows.

### The first wave — read only

11. **The code introduces the reading first and separately.** The tools of the first wave are `get_ad_object`, `get_ad_membership`, `find_ad_objects`, `get_ad_domain_info`, `get_ad_health` and `get_ad_stale_objects`. All of them only read, they do not require a confirmation and they have no separate switch.
12. **The maintenance of the domain and the forest enters the first wave, because it reads.** Replication, the state of the domain controller services, FSMO, trusts, sites, password policies together with PSO, stale objects — this is diagnostics. Operations that change the topology do not enter the product at all. Such operations are the seizure of the FSMO role, the cleanup of metadata and a forced replication. This is a decision, not a postponed item.

### The frame of the write, accepted in advance

13. **The write into the directory is off by default.** `WINRIG_ALLOW_AD_WRITE` with the value `false`; in the off state the router removes the tools and does not declare them to the agent — as `write_file` and `run_command` in ADR-0013 §2.
14. **Each write requires a confirmation (DR-5), and the confirmation text holds the DN.** `sAMAccountName` does not distinguish an object: the same name occurs in different OUs and in different domains of the forest. The operator confirms the object, not the name.
15. **A modification addresses exactly one object, named explicitly.** The code does not support changes by a filter or by the result of a search. The reason is the same as the one for which DR-6 protects recursive deletion. A mistake in a filter changes a thousand objects in one call, and the operator has nothing to roll it back with.
16. **The code rejects protected objects before the call to the host** — a direct analog of `is_protected_path`. They are `krbtgt`, the built-in `Administrator`, Domain Admins, Enterprise Admins, Schema Admins and other objects with `adminCount=1`. They also include the Domain Controllers container and the domain object itself.
17. **The code forbids the write into some attributes unconditionally, and no list opens them.** They are `ntSecurityDescriptor`, `sIDHistory`, `msDS-AllowedToActOnBehalfOfOtherIdentity`, `servicePrincipalName`, `unicodePwd` past the password tool, and `member` and `memberOf` past the membership tool. Each of them is a path to the capture of the domain in one call, not a field of the card of an employee.
18. **The other attributes follow the allowlist `WINRIG_AD_WRITABLE_ATTRIBUTES`.** The allowlist has the same semantics of an empty list as `WINRIG_ALLOWED_HOSTS` and `WINRIG_ALLOWED_COMMANDS`: empty means "any attribute, except the unconditionally forbidden ones". This is the mechanism of the "editing rules": the rule lives in the configuration of the operator, not in the description of the tool.
19. **The code redacts a password from an argument in the answer and unconditionally in the audit log (DR-4), and it names the residual exposure directly.** The password reaches the directory as the text of the command on the domain controller. It also gets into the logs of the domain controller: script block logging, ETW and a process audit. The redaction of winrig closes its answer and its audit log. It does not close the logs of the domain controller, and it cannot. This is not a defect of the implementation: the secret must reach the directory.
20. **A password change and the creation of an account require a protected channel to the domain controller.** An unencrypted connection is a refusal, not a warning.
21. **The creation of an account requires an explicitly named OU and creates the account off,** until the operator sets a password. The default "Users container" hides a decision that has consequences in the domain: policies and delegation tie to the OU.
22. **The audit log of a write records the DN, the name of the attribute, the previous value and the new value.** `set_registry` shows old vs new in the same way.
23. **The deletion of directory objects does not enter this frame.** It needs its own protection after the model of DR-6, including the behavior of the AD recycle bin. It also needs a separate decision. Before that decision `remove_ad_object` does not exist.

## Consequences

- The absence of work with the directory stops being an implicit property of the code. The route, the frame and the boundaries are recorded before the first line of the implementation.
- The number of declared tools grows from 38 to 44 (visible to the agent by default from 37 to 43). The criterion AC-PRF-48 and the tests `server::tests::tool_router_lists_registered_tools`, `tests/stdio_mode.rs::stdio_serves_mcp_over_clean_stdout` change in the slice W19.
- The ADR admits it directly: the reading of the directory is also an exposure. `find_ad_objects` and `get_ad_membership` allow the download of the structure of the organization, the composition of the privileged groups and the list of stale accounts. This is a ready map for reconnaissance. A ceiling on the results and the audit log of calls limit this. A prohibition of enumeration does not exist, and this is a choice, not an oversight.
- The ADR admits it directly: with `WINRIG_ALLOW_AD_WRITE=true` and an empty `WINRIG_AD_WRITABLE_ATTRIBUTES` the protection stays only on the unconditionally forbidden attributes and the protected objects. Every other directory attribute is available for a write. This is a choice of the operator, not a property that winrig keeps. The combination with `WINRIG_CONFIRM_FALLBACK=proceed` (ADR-0013 §19) means a change of the directory by the decision of the agent without the participation of a person.
- The tie to the domain controller means that the operator must allow the domain controller in `WINRIG_ALLOWED_HOSTS` (DR-7). The account of the profile must also have the right to connect to the domain controller over WinRM. This is usually an administrative privilege, and the ADR names it here, so that the operator does not learn it at the first call.
- The choice of `System.DirectoryServices` instead of RSAT was not checked on a live domain controller: there is no Windows host in the environment (Q-08). The ADR records the assumption as Q-15, and the first live call closes it.
